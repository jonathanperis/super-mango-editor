## Raylib migration roadmap — implementation detail

### Recommended architecture

- **Dependency:** raylib's C library, initially 6.0; no language binding or raygui is needed. Keep a checked-in source/version/checksum manifest and explicit dependency bootstrap into workspace-local ignored build storage. Use CMake only for the dependency's out-of-source build, with the application's Makefile retaining its existing targets. A vendored source layout may replace the bootstrap if phase 0 identifies a concrete reproducibility benefit; record the decision before broad conversion.
- **Application boundary:** call raylib directly in rendering/resource modules. Add small project-owned types/functions only where behavior requires them: integer hitboxes, semantic input, user-data paths and native dialogs. Do not create a second renderer API mirroring SDL. Standardize SDL integer aliases to stdint.h types without changing signedness or timer units accidentally.
- **Lifetime:** one game-process window/render context is shared by menu, settings and gameplay. Screen transitions release screen resources while AppSession retains the platform context. The editor is a separate executable and context. Texture2D/Font/Sound/Music copies do not transfer ownership; mark owners/borrowers and zero invalidated values. Fonts/aliases/textures must be released before their underlying atlas/sample/device/context. Keep asynchronous profile save completion ahead of normal final teardown.
- **Rendering:** render the 400x300 game to a point-filtered target and present with correct aspect/viewport mapping. Account for render-texture Y orientation and DrawTexturePro origin/negative-source-size flip conventions. Keep editor screen/canvas/panel transforms distinct. Port alpha modulation to per-draw tint and clipping to scissor coordinates, checking restoration across layers. Retain integer collision math and convert only presentation coordinates.
- **Input:** reuse the existing action masks and test physical-state seam. Introduce only the command records needed by current menus/editor/replay; do not emulate SDL_Event. Drain raylib key/character queues once and preserve command order where supplied; sampled button edges need an explicit cross-device same-frame policy. Keep press/release latches and touch quick-tap buffering. Frame polling and EndDrawing must not both advance input accidentally. Escape remains a game/editor command, not an unconditional process exit.
- **Compatibility:** retain version-1 profile wire numbers through explicit project-owned translation, so old/new sessions can still compare and save the same format. This is a data codec, not an SDL runtime shim. Verify every currently valid saved key/button category, including keyboard-layout-dependent and extra controller buttons. If raylib cannot represent one, stop that compatibility decision for user resolution instead of dropping the field. Keep existing OS preference paths and browser storage identity.
- **Audio:** raylib music needs pumping; a mechanical Mix_PlayChannel-to-PlaySound replacement can collapse overlapping instances. Use an explicitly bounded voice policy matched to the existing mixer behavior, including per-play volume and stop/unload ordering. Individual sound assets can be optional, but current game startup fails if the audio device cannot open. Preserve that distinction and prove a CI device/test strategy without treating muted execution as playback proof.
- **OS features:** raylib does not replace every SDL service. Preserve the existing native file-dialog integration and add equivalent confirmation/error/recovery operations there; preserve cancel/default-button behavior and transactional save decisions. Keep platform path and process APIs behind their existing responsibility boundaries. Remove SDL-only initialization workers/test instrumentation if unnecessary; any remaining actual concurrency uses appropriate C/OS primitives with main-thread raylib ownership.

1. **Baseline first:** phase 0 records current test results, seeded `SMOKE_STATE` outputs and representative rendering/editor/audio behavior using task-owned data. Include raylib and the used bundled-component notices; refresh current release instructions and compile/sprite examples. Do not rewrite historical credits/evidence.
